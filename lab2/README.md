1) **Зачем нужен паттерн Builder, если можно всё создавать через конструкторы?**

Builder нужен, потому что он решает проблему сложных обьектов и позволяет создавать их по шагам. 
Конструкторы не справляются, когда у объекта много опциональных параметров. 
Это приводит либо к телескопическим конструкторам (десятки конструкторов на все комбинации), либо к монструозному конструктору с кучей параметров, 
большинство из которых простаивают. Builder решает это тем, что выносит процесс сборки в отдельный объект и позволяет вызывать только нужные шаги, 
а не передавать все параметры сразу.

3)  **Чем отличается Adapter и Bridge, как Вы поняли?**
    
- Adapter делает несовместимые интерфейсы совместимыми.Он решает проблему, когда интерфейсы уже несовместимы и их нельзя изменить. 
Адаптер делает один интерфейс понятным для другого.
 
- Bridge разделяет абстракцию и реализацию, чтобы они менялись независимо (архитектурное решение на этапе проектирования).

_"Мост проектируют загодя, чтобы развивать большие части приложения отдельно друг от друга.
Адаптер применяется постфактум, чтобы заставить несовместимые классы работать вместе."_

4) **Приведите пример, как язык Java использует паттерн проектирования Iterator.**

В Java все коллекции (например, ArrayList, HashSet) реализуют интерфейс Collection, который объявляет метод получения итератора.
Этот итератор позволяет последовательно обходить элементы коллекции, не раскрывая её внутреннее устройство.

Java использует Итератор на уровне стандартной библиотеки, а именно в Java Collections Framework (JCF).

Интерфейсы коллекций и итераторов
Статья описывает структуру паттерна:

- Итератор - интерфейс для доступа и обхода элементов

- Конкретный итератор - реализует алгоритм обхода конкретной коллекции

- Коллекция - интерфейс для получения итератора

- Конкретная коллекция - возвращает итератор, связанный с ней


5) **В каких принципах программирования, изученных за этот год, встречаются паттерны проектирования “шаблонный метод”, “стратегия”? Какие ключевые слова языка java с ним связаны?**

Template Method встречается, когда в базовом классе задаётся общий алгоритм, а отдельные шаги переопределяются в наследниках. 
В Java это видно через abstract классы, extends и @Override.

Strategy встречается, когда поведение можно менять во время выполнения, передавая разные реализации через интерфейсы. 
В Java это interface, implements и, например, лямбды (как при передаче Comparator в сортировку).

Template Method связан с:
- наследованием (inheritance)
- частично с принципом открытости/закрытости (OCP) — можно расширять поведение через наследников, не меняя базовый класс

Strategy связан с:
- композицией вместо наследования
- инкапсуляцией алгоритмов
- принципом открытости/закрытости (OCP) — можно добавлять новые стратегии без изменения кода

Ключевые слова java связанные с ним 

Template Method: abstract, extends, @Override, final

Strategy: interface, implements, new
